# Tephra – app

The graphical app, built with Flutter on top of the Rust core in `../crates`. What it can do and what is still missing
is described in the [README](../README.md) of the repository ([deutsch](../README.de.md)).

## Layout

- `lib/` – the user interface (Dart). `lib/src/ui/` holds the screens, `lib/src/session.dart` a terminal session,
  `lib/src/text.dart` the German and English texts.
- `rust/` – the crate `tephra_bridge`: the interface between the user interface and `tephra-core`. Secrets stay on the
  Rust side; the user interface can set passwords and keys but never reads them back.
- `lib/src/rust/` and `rust/src/frb_generated.rs` – generated by
  [flutter_rust_bridge](https://github.com/fzyzcjy/flutter_rust_bridge). Do not edit; regenerate instead.
- `integration_test/` – a test that drives the real app against the SSH test server of `tephra-ssh`.

## Build

Requirements: the [Flutter SDK](https://docs.flutter.dev/get-started/install) 3.50 or newer, Rust 1.90 or newer and
the native toolchain of the platform (Windows: Visual Studio with "Desktop development with C++"; Linux: clang, CMake,
Ninja, pkg-config and the GTK 3 development files).

```bash
flutter build windows --release      # or: flutter build linux --release
flutter build apk --release          # Android, all architectures
flutter run -d windows               # during development
```

Android additionally needs a JDK 17 (`flutter config --jdk-dir <path>` if it is not the default Java), the Android SDK
with platform 36 and NDK 28.2 (`sdkmanager "ndk;28.2.13676358"`), and the Rust targets:

```bash
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
```

The release build is signed with the debug key for now (`android/app/build.gradle.kts`); replace that before
publishing. On Android the vault lives in the private data folder of the app and is excluded from backup
(`android/app/src/main/res/xml/data_extraction_rules.xml`).

The Rust crate is compiled by the build hook in `hook/build.dart`; there is no separate step.

After changing the interface in `rust/src/api/`, regenerate the bridge:

```bash
cargo install flutter_rust_bridge_codegen --version 2.13.0
flutter_rust_bridge_codegen generate
```

## Test

```bash
flutter analyze

# in the repository root: start the SSH test server, it prints its port
cargo run -p tephra-ssh --features testing --example test_server

# in app/: TEPHRA_VAULT must point to a file that does not exist yet
TEPHRA_VAULT=/tmp/tephra-test/vault.tephra flutter test integration_test -d windows --dart-define=TEPHRA_TEST_PORT=<port>
```

`TEPHRA_VAULT` selects the vault file, as it does for the command line. Without it the app uses the same default
location as `tephra`.

On an Android emulator the app reaches the test server of the host at 10.0.2.2. The app must not be installed yet,
because the test expects to create the vault:

```bash
flutter test integration_test -d emulator-5554 --dart-define=TEPHRA_TEST_HOST=10.0.2.2 --dart-define=TEPHRA_TEST_PORT=<port>
```

The debug build is large (about 200 MB); the emulator needs enough free storage for it.
